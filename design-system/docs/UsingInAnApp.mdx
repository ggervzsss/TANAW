# Using the design system in an app

Both apps already have the copies in `src/design-system/` and import the shared stylesheet right after the tokens in `src/index.css`:

```css
@import "tailwindcss";
@import "./styles/tanaw-tokens.css";
@import "./design-system/styles/components.css";
```

Import components from the copy's index (a relative path from the file you are in):

```tsx
import { Badge, Button, Card, CardHeader, MetricStrip } from "../design-system";

<Card>
  <CardHeader title="Plaza camera" actions={<Button variant="secondary">Settings</Button>} />
</Card>;
```

## Rules

1. **Never edit `src/design-system/` in an app.** It is generated; the drift test fails if you do. Change `design-system/src/` and run the sync.
2. **Keep app logic in the app.** Shared components are presentational: they take values and callbacks. Sign-in, API calls, Electron bridges and password rules stay in each app and are passed in (see `PasswordRequirements`, which takes the app's policy verdict).
3. **Older component names still work.** Each app's earlier components (`SelectDropdown`, `StatusBadge`, `ModalFrame`, `UnifiedMetricsHeader`, `InfoTooltip`, …) are now thin wrappers over the shared ones, so existing screens use the shared code without import changes. Prefer the shared names in new code.
4. **Use role tokens** (`text-(--tanaw-text)`, `bg-(--tanaw-surface)`) rather than raw colours, so dark mode works without `dark:` variants.
